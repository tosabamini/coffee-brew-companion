# Coffee Brew Companion

自作のBLE電子スケール(ESP32 + HX711)と連携し、ハンドドリップの注湯をリアルタイムでグラフ化・記録するFlutterアプリ。

- **`coffee_brew_smartphoneapp/`** — Flutterモバイルアプリ
- **`coffee_scale_ble/`** — ESP32ファームウェア(HX711読み取り + BLE GATT配信)

開発の背景・アーキテクチャ・用語解説など詳細な資料は [APP_OVERVIEW.md](APP_OVERVIEW.md) を参照。Claude Codeへの作業指示は [CLAUDE.md](CLAUDE.md) を参照。

## 実装済み機能

### 計測・BLE連携
- 自作スケールとのBLE接続・切断、Tare(風袋引き)
- Start/Stopで重量×時間の折れ線グラフをリアルタイム描画(`CustomPainter`自前実装、外部グラフライブラリ不使用)
- **自動スタート**: 「自動」トグルで武装し、直近6サンプルの最小値から+2.0g増加で計測を自動開始。自作スケールのノイズ(±0.5g程度)に対するマージンを持たせた閾値。豆量計測中は判定停止

### 抽出中のリアルタイム指標(ヒーローカード)
- **流量(FLOW)**: 直近約1秒の重量差分からg/sを算出
- **ペースガイド(PACE)**: レシピのステップ目標を線形補間し、実測との差分を「ON PACE / +Xg先行 / Xg遅れ」で色分け表示
- **レシオ(RATIO)**: 豆量と現在重量から1:Nを表示
- **次の注湯目標**: 「次: 0:45 までに 120g」を抽出中に表示

### レシピ
- 複数レシピの保存・切替(最大6段階の注湯ステップ)、豆量に応じた目標量の自動スケーリング
- 豆量計測ボタン(タレ→計量→決定)
- レシピ選択はボトムシート形式(実機での縦空間確保のため)

### 記録・分析
- セッション保存(豆の産地・品種・精製方法・焙煎度・標高・フレーバーノート等)
- **ブリューレシオ / 抽出収率(EY%)**: TDS(屈折計測定値)と豆量からその場で自動計算。詳細画面で後編集可
- **ゴースト表示**: グラフに過去セッションの曲線を半透明で重ね、再現性を確認
- **統計ダッシュボード**: 総杯数・今月の杯数・豆消費量・平均抽出時間・平均レシオ・平均収率・週別抽出数のバーチャート・焙煎度分布
- **豆在庫・エイジング管理**: 焙煎日からの経過日数バッジ(休ませ中/飲み頃/そろそろ/経過長め)、残量バー、消費記録
- **CSVエクスポート**(`share_plus`経由): 全セッションサマリ(履歴画面)、重量点データ(詳細画面)。UTF-8 BOM付きでExcel対応
- セッション詳細をPNG画像として書き出し
- SCAフレーバーホイールの自前描画・カスタマイズ(部分実装、下記「保留中」参照)

### AI連携
- 豆パッケージ写真からClaude Vision(`claude-haiku-4-5`)で産地・品種・焙煎度等を自動入力

### デザイン
- 独自デザインシステム(`lib/theme/`): クレマ色の背景+エスプレッソ色のヒーローカード、Fraunces/Zen Kaku Gothic New/IBM Plex Monoのフォント使い分け
- カスタムページ遷移(フェード+スライド)
- グラフ最優先のレイアウト(AppBar廃止、レシピ選択のボトムシート化、ナビゲーションバーとの干渉解消)
- 起動アニメーション(抽出カーブが描かれながら重量カウンターが回る、約1.4秒)
- オリジナルアプリアイコン(ドリッパー+滴+スケール台)

## 保留中: フレーバーホイールの再設計

現状のフレーバーホイールは、大分類・中分類・小分類の全リングを1画面に同時表示しているため、外周セグメントの弧長に対して文字が入らず可読性が低い。次のいずれか(または組み合わせ)で再設計する方向。

| 案 | 概要 | 長所 | 短所 | 難易度 |
|----|------|------|------|--------|
| **A. 回転ダイヤル+読み取り窓** | 色のみのダイヤルにし、12時位置の固定針が指すセグメント名を中央に大きく表示。境界を跨ぐごとにハプティクス | 回転操作が「選ぶ」動作そのものになり爽快。文字サイズ無制限 | 一覧性が下がる | 中 |
| **B. ズーマブル・ドリルダウン** | 大分類9個のみを全径表示→タップで中分類に展開→さらに小分類へ。中央にパンくず | 各階層で文字が大きく取れる。定番UXで迷わない | 状態管理・展開アニメーションの実装コスト | 中〜高 |
| **C. 中央ラベル+タップハイライト** | リング構成は維持し文字を色のみに削減。タップしたセグメントの名前を中央と下部カードに表示 | 改修が最小限。色の地図としての一覧性は維持 | 文字を「探す」操作ができない | 低 |
| **D. 描画の磨き込み(併用推奨)** | 弧に沿った本物のカーブテキスト、弧長に応じたフォント自動縮小、テーマフォント/配色への統一、セグメント間ヘアライン | どの案でも効く仕上げ | 単体では可読性の根本解決にならない | 低 |

**現時点のおすすめ**: B(ドリルダウン)+ D(磨き込み)。回転操作は各階層でそのまま活かせて、かつ全階層で文字サイズ問題が構造的に解消するため。「回転そのものを主役にしたい」という意向が強ければA、またはA/Bの折衷(各階層で回転+針選択、タップで下の階層へ)も検討可。

対象ファイル: `coffee_brew_smartphoneapp/lib/features/flavor_wheel/`
